# Панель статуса: три исправления после редизайна

## Overview
- выполняется **на ветке `panel-redesign`** (редизайн панели, ещё не влит в `master`); исправления найдены при просмотре демо
- три недочёта и согласованные в brainstorm решения:
  1. диапазон скорости с дробями (`8802.5–11995.8/с`) → **целые от 10/с** с разделителем тысяч, дробь (один знак) — только ниже 10/с; то же для числа в колонке «скорость»
  2. полоса догона показывает 100% задолго до конца (процент от стартового лага 28 ч: на хвосте лаг 57 с — уже 100%) → **линейная полоса с округлением вниз и максимумом 99%**, пока догон активен; про хвост говорят лаг числом и «~… до 0»
  3. графики плоские ~минуту после догона (масштаб 0..max окна задают точки догона) → **масштаб по последним 15 с**: старые столбики выше упираются в `█`, диапазон справа остаётся настоящим
- репликатор, `Status`, раскладка и режимы панели не меняются

## Solution Overview
- `fmtRate(v float64) string` в `render.go` — общий формат скорости операций для числа и диапазона
- полоса догона: потолок 99% в `lagLine`, `progressBar` и процент — округление вниз с поправкой на погрешность float
- `sparkline` берёт масштаб не по всему окну, а по последним 5 колонкам; значения выше масштаба ограничиваются верхним уровнем

## Technical Details

### 1. `fmtRate`
- `v ≥ 10` → `fmtCount(int64(math.Round(v)))`: `10` → `10`, `8802.5` → `8 803`, `12000` → `12 000`
- `v < 10` → `fmtFloat(v)`: `0` → `0`, `0.4` → `0.4`, `9.94` → `9.9`
- `rateLine`: число в колонке — `fmtRate(v.st.Rate)`, диапазон — `fmtRate(lo) + "–" + fmtRate(hi)`
- трафик (`fmtBytes`) не меняется

### 2. Процент и полоса
- потолок 99% — в одном месте, в `lagLine`: `frac := min(v.catchUp.frac(), 0.99)`; процент и полоса считаются от этого `frac`
- округление вниз **с поправкой на погрешность float**: процент — `int(math.Floor(frac*100 + 1e-9))`, клетки в `progressBar` — `int(math.Floor(min(max(frac, 0), 1)*float64(cols) + 1e-9))` (без поправки `0.58*100` = `57.99999999999999` → 57, а у реальных лагов ~0.4% пар секунд дают процент на единицу меньше: старт 60 с, лаг 48 с → 19% вместо 20%)
- `progressBar` остаётся общей: только округление вниз, без потолка; смысл «не больше 99%» — в `lagLine`
- примеры: стартовый лаг 28 ч, лаг 57 с → `frac` 0.99 → `99%`, 19 `█` + 1 `░`; `frac` 0.58 → `58%`, 11 `█`; 0.2 → 4 `█`; 0 → `0%`, 20 `░`
- обновить doc-комментарии `progressBar` и `lagLine`

### 3. Масштаб графика
- `sparkScale = 5` — число последних колонок (15 с), по которым берётся масштаб
- `top` = максимум средних последних `min(5, len(avgs))` колонок (правая колонка может быть неполной — входит как есть)
- если этот `top == 0` (последние 15 с — нули: повтор, остановка) — `top` = максимум всех колонок (как сейчас); если и он 0 — все заполненные колонки `▁`
- уровень: `idx := int(math.Round(min(v/top, 1) * float64(len(sparkLevels)-1)))` — колонки выше `top` дают `█`; ограничение **до** преобразования в `int` (иначе огромное отношение даёт выход за массив)
- обновить doc-комментарий `sparkline` (сейчас «относительно наибольшего среднего» — станет неверно)
- диапазон справа (`rateLine`) — по-прежнему `мин–макс` всех колонок окна (`sparkColumns`), не по масштабу
- правило в одном месте (`sparkline`) — действует для всех трёх графиков (скорость, источник ↓, цель ↑)
