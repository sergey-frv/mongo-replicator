# mongo-replicator

Репликация одной базы MongoDB между кластерами через change streams. Код — `cmd/mongo-replicator` (CLI, `main.go`) и `cmd/mongo-replicator/replicator`.

## Команды
- `make test` — unit-тесты в контейнере `app`
- `make test-integration` — интеграционные (`-tags integration`, `-p 1`); compose поднимает `mongo-src`, `mongo-dst`, `toxiproxy`
- `make lint`, `make build` (`build` делает `go mod tidy` + `go mod vendor`, зависимости вендорятся)

## Где живёт состояние
- **на цели** — один документ `{_id: "checkpoint"}` в `<dst-db>._replicator_checkpoint` (`ckptColl`/`ckptID`, `checkpoint.go`): позиция, пара баз, аренда. Отдельной служебной базы нет, на цели нужен только `readWrite` на `--dst-db`; `SystemDBs` — только `admin`, `config`, `local`
- служебную коллекцию **всегда** отсекает `streamPipeline` (`$match` по `ns.coll`), но rename проходит фильтр намеренно: rename в `_replicator_checkpoint` или из него ловит `applyDDL` до `checkLease()` и возвращает перманентную `ErrReservedCollection`. Меняя фильтр, сохранять пропуск rename
- в тестах списки коллекций цели сравнивать через `collNames` (исключает служебную), не через `ListCollectionNames`
- **на машине** — трафик процесса в `<state-dir>/<dst-db>.<8 hex sha256(ключа кластера)>.json` (`statefile.go`); потеря файла не ломает репликацию, ошибки записи — WARN. Сводка «на машине» — сумма всех `*.json` каталога
- ключ кластера (`clusterKey`) — по URI цели как написан, не по разрешённым хостам: `srv:<host>` для `mongodb+srv` (SRV с `srvMaxHosts` даёт случайное подмножество), для `mongodb://` — хосты в нижнем регистре с портом, отсортированные
- битый файл или чужая пара баз/кластер — файл переносится в сторону (`.corrupt-*`/`.mismatch-*`), не удаляется; база файла читается один раз за процесс и только после проверки пары баз
- пустые `Config.StateFile`/`StateDir` выключают файлы и сводку — так работает большинство интеграционных тестов
- файл пишет только владелец аренды: загрузка — после `acquireLease` и `checkDBs` и только со свежей арендой (`checkLease`), писатель пропускает запись при устаревшей аренде, последняя запись в `Release` — после подтверждающего `renewOnce` и **до** снятия аренды (иначе преемник прочитает файл без неё)
- `moveAside` не заменяет занятое имя переноса (`Rename` на Unix заменил бы прежний `.corrupt-*`)

## Тесты
Правила для **новых** тестов и хелперов; существующие при правке не переписываются и не переименовываются.
- **раскладка**: юнит — `<file>_test.go` рядом с `<file>.go`; исключение — `main.go`, его тесты по темам: `options_test.go` (`parseOpts`, `stateDir`), `mask_test.go`, `errors_test.go`, `log_test.go` (логгер и общие хелперы `restoreLogger`, `captureStdout`), остальное — `main_test.go`; интеграционный — `<область>_integration_test.go` с тегом `integration`; хелпер, нужный ≥2 файлам, — `harness_integration_test.go`, хелпер одной области — в её файле (компилятор размещение не проверяет: пакет один); новый тест — в файл своей области, новая область — новый файл
- **структура**: «дано → действие → проверка», блоки через пустую строку; без логики в теле, кроме перебора таблицы; ожидания — литералы
- **проверки**: новые проверки — testify: `require` (продолжать бессмысленно) / `assert` (независимые проверки); `assert.Equal(t, want, got, "контекст")`; ошибки — `ErrorIs`, текст — только когда важен сам текст (подсказки оператору). Правка теста не обязывает переписывать его остальные проверки
- **табличные тесты** — когда случаи отличаются только данными; флаги и `setup`-функции в таблице → отдельные тесты
- **хелперы**: `t.Helper()` первой строкой; `t` — первым аргументом, после `ctx`, если он есть (revive `context-as-argument`); новый хелпер, который может завалить тест, называется `require…`/`assert…` (существующие `prepare`, `srcNow`, `readLease` и т. п. имён не меняют)
- **время**: `require.Eventually` с сообщением вместо `time.Sleep`; сон — только для серверного времени (аренда, `$$NOW`); логика по «сейчас» получает время параметром
- **изоляция**: `t.TempDir`, `t.Setenv`, `t.Cleanup`; тест не зависит от порядка запуска. Исключение намеренное: `lastSrcSec` переносит между тестами время последней операции обвязки, чтобы `srcNow` не захватил хвост предыдущего теста — не «чинить»
- **имена**: интеграционные — `TestIntegration<Что>`, область задаёт имя файла и в имени теста не обязательна; тесты известных ограничений — `TestLimitation<Что>` (на них ссылается README); подтест называет случай, а не номер

## Интеграционные тесты
- обвязка (`TestMain`, `newIT`, `start`/`startOn`, `runner`, `withState`, `writeCkpt`, `readLease`, `populateProxies`…) — в `harness_integration_test.go`
- репликатор — только через `newIT`/`newTrafficIT`/`nc.newIT` (короткие аренда и `stateEvery`), не через голый `New`; менять поля репликатора (`stateEvery`) — до `startOn`, иначе гонка с `Run`
- файлы состояния включает `withState(cfg, t.TempDir())`; `shortActive(t)` меняет пакетную `stateActiveFor` — `t.Parallel` в пакете нельзя

## Сетевые тесты (Toxiproxy)
- сетевые хелперы (`netCase`, `startRetry`, `hang`, `startWriter`…) — в `network_integration_test.go`, создание прокси (`populateProxies`) — в обвязке
- модуль `github.com/Shopify/toxiproxy/v2` и образ закреплены на **v2.12.0**: v2.13.0 требует go 1.27, а проект и `Dockerfile.dev` на go 1.26
- URI через прокси (`IT_SRC_PROXY_URI`/`IT_DST_PROXY_URI`) обязаны иметь `directConnection=true`, иначе драйвер возьмёт адрес узла из конфигурации replica set и пойдёт мимо прокси
- прокси из `Populate` нельзя сразу `Enable`/`Disable` (409) — брать их через `Proxy(name)` (`populateProxies`)
- «зависание» — `timeout`-токсик на **обоих** направлениях (`hang`); только `downstream` (умолчание) пропускает запросы до сервера
- без `IT_PROXY_API` сетевые тесты пропускаются
- сетевой тест начинается с `nc := netCase(t)` (клиенты через прокси, cleanup снимает токсики); цикл повторов как в `main` — `startRetry`
